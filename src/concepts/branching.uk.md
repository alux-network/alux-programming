Розгалуження, детермінізм, конфлюентність, еквівалентність трас і бісимілярність стосуються альтернатив в обчисленні. Це не одна й та сама властивість.

```admonish note title="Семантичне місце"
Розгалуження потоку керування — це операційна структура. Конфлюентність — властивість відношення редукції. Еквівалентність трас і бісимілярність порівнюють поведінку. Денотаційна рівність порівнює значення у вибраній семантичній області. У коректному проєкті прямо вказують потрібну рівність, а не неформально переходять від одного поняття до іншого.
```

## Еквівалентність поведінки {#behavioral-equivalence}

Паралельні й інтерактивні програми рідко мають лише один кінцевий результат. Зазвичай починають із **системи переходів із мітками**:

$$ \mathcal{L} = (S, A_{\tau}, \to) $$

де $S$ — множина станів, $A_{\tau}$ — множина міток спостережуваних дій разом із внутрішньою дією $\tau$, а $\to\;\subseteq S \times A_{\tau} \times S$ — відношення переходів. Запис $p \xrightarrow{a} p'$ означає, що стан $p$ може виконати дію $a$ і перейти до $p'$.

Еквівалентність поведінки визначає, які відмінності між такими системами навмисно ігнорують:

*   **Спостереження лінійного часу** простежують завершені чи часткові виконання й фіксують події на їхньому шляху
*   **Спостереження розгалуженого часу** також зберігають інформацію про доступні альтернативи й момент остаточного вибору

Тому дві системи можуть мати однакові траси, але різну структуру розгалуження. Одна може вибрати між двома діями до взаємодії, а інша — відкласти вибір до її завершення. Послідовності дій однакові, але майбутні можливості — ні.

[Спектр еквівалентностей лінійного й розгалуженого часу](https://ir.cwi.nl/pub/5685/5685.pdf) ван Ґлаббека систематизує такі еквівалентності поведінки. Це не рейтинг від слабких до сильних: кожна точка спектра зберігає свій набір спостережень.

## Розгалуження в програмах Rust {#branching-in-rust-programs}

`if` вибирає одну гілку за умовою:

```rust,noplayground
fn sign(x: i32) -> i32 {
    if x > 0 {
        1
    } else if x < 0 {
        -1
    } else {
        0
    }
}
```

`match` вибирає одну гілку за значенням:

```rust,noplayground
fn day_type(day: &str) -> &str {
    match day {
        "Saturday" | "Sunday" => "Weekend",
        "Monday" | "Tuesday" | "Wednesday" | "Thursday" | "Friday" => "Weekday",
        _ => "Unknown",
    }
}
```

За фіксованих вхідних даних у детермінованій мові ці конструкції вибирають передбачуваний шлях потоку керування. Це **детермінізм**, а не конфлюентність.

## Що означає конфлюентність {#what-confluence-means}

Відношення редукції є конфлюентним, якщо два перетворення того самого терма можна знову звести докупи:

$$ \begin{array}{ccccc} && a && \\ & \swarrow^{*} && \searrow^{*} & \\ b &&&& c \\ & \searrow^{*} && \swarrow^{*} & \\ && d && \end{array} $$

Формально, якщо:

$$ a \to^* b \quad\text{and}\quad a \to^* c $$

то має існувати деяке `d`, для якого:

$$ b \to^* d \quad\text{and}\quad c \to^* d $$

Конфлюентність допускає кілька шляхів редукції. Вона стверджує, що ці шляхи узгоджуються, бо можуть привести до спільного наступника.

## Детермінізм і конфлюентність {#determinism-and-confluence}

У детермінованого відношення редукції з кожного стану можливий не більш як один наступний крок. Отже, воно конфлюентне у простому сенсі: немає конкуруючих однокрокових виборів, які треба узгоджувати.

Обернене твердження хибне. Система може допускати кілька порядків редукції й лишатися конфлюентною, якщо всі вони зрештою узгоджуються.

Звичайні вирази Rust `if` та `match` демонструють детермінований вибір, але самі по собі не показують нетривіальну суть конфлюентності.

## Черч—Россер {#churchrosser}

Теорема Черча—Россера стверджує конфлюентність для редукції лямбда-числення: якщо терм різними шляхами редукції переходить до двох результатів, вони мають спільне зведення.

Якщо існує нормальна форма, конфлюентність гарантує її унікальність. Це підтримує рівняннєве міркування, адже порядок обчислення не змінює кінцеву нормальну форму.

Не поширюйте цей результат на довільні імперативні програми. Побічні ефекти, недетермінований розклад, збої й спостереження проміжних станів можуть розрізняти порядки редукції.

## Траси {#traces}

**Траса** фіксує послідовність спостережуваних дій чи станів. Трасова семантика навмисно зберігає більше операційної інформації, ніж семантика лише результатів.

Дві чисті функції можуть повертати однаковий результат, проходячи різні внутрішні кроки. Якщо ці кроки відкинуто, у денотації за результатом функції рівні. У трасовій семантиці вони не обов’язково рівні.

За наявності ефектів перестановка умов може змінити спостереження:

```rust,noplayground
fn is_admin() -> bool {
    println!("checked admin");
    true
}

fn is_user() -> bool {
    println!("checked user");
    true
}
```

Перевірка `is_admin` першою або перевірка `is_user` першою може повернути еквівалентні класифікації, але створити різні траси виводу.

Проєктне запитання полягає в тому, чи належить цей вивід до вибраної семантичної області.

## Еквівалентність трас {#trace-equivalence}

Дві системи є еквівалентними за трасами, якщо згідно з вибраною моделлю трас вони допускають ті самі спостережувані траси.

Еквівалентність трас може не враховувати структуру розгалуження. Дві системи можуть породжувати ті самі траси, хоча одна фіксує вибір раніше за іншу. Для інтерактивних і паралельних систем це може мати значення.

## Бісимілярність {#bisimulation}

Бісимілярність співвідносить дві системи переходів покроково. Кожному спостережуваному кроку однієї системи має відповідати крок іншої, а отримані стани й далі мають бути співвіднесені.

Поширені різновиди:

*   **сильна бісимілярність**, яка зіставляє окремі переходи
*   **слабка бісимілярність**, яка абстрагується від вибраних внутрішніх переходів
*   **розгалужена бісимілярність**, яка ігнорує внутрішню роботу, зберігаючи важливу структуру вибору

Бісимілярність часто є сильнішим способом порівняти поведінку, ніж еквівалентність трас, адже вона враховує, які альтернативи лишаються доступними під час взаємодії.

<summary><strong>Походження та формальні визначення</strong></summary>

Мілнер розробив спостережувану еквівалентність для процесів взаємодії у [*A Calculus of Communicating Systems*](https://www.lfcs.inf.ed.ac.uk/reports/86/ECS-LFCS-86-7/ECS-LFCS-86-7.pdf). Парк згодом охарактеризував відповідну еквівалентність коіндуктивно у [*Concurrency and Automata on Infinite Sequences*](https://wrap.warwick.ac.uk/id/eprint/47224/1/WRAP_Park_cs-rr-035.pdf), сформулювавши відношення найбільшої нерухомої точки й метод доведення, який тепер називають бісимілярністю. Мілнер перейняв і розвинув цей метод як основу міркування про поведінку процесів.

**Сильна бісимілярність.** Для систем переходів із мітками відношення $R$ є сильною бісимілярністю, якщо $p\mathrel{R}q$ виконується, а для кожної дії $a$:

*   якщо $p\xrightarrow{a}p'$, то існує $q'$, для якого виконується $q\xrightarrow{a}q'$ та $p'\mathrel{R}q'$; і
*   якщо $q\xrightarrow{a}q'$, то існує $p'$, для якого виконується $p\xrightarrow{a}p'$ та $p'\mathrel{R}q'$.

Два стани бісимілярні, якщо їх пов’язує певна бісимілярність. Визначення є коіндуктивним: після зіставлення переходу наступні стани мають знову виконувати те саме зобов’язання щодо поведінки.

**Розгалужена бісимілярність.** У поширеному формулюванні, що не розрізняє дивергенцію, симетричне відношення $R$ є розгалуженою бісимілярністю, якщо $p\mathrel{R}q$ та $p\xrightarrow{a}p'$ означають один із двох варіантів:

*   $a = \tau$ і $p'\mathrel{R}q$; або
    
*   існують стани $q_0$ та $q'$, для яких
    
    $$   q \xRightarrow{\tau} q_0 \xrightarrow{a} q',   \qquad   p\mathrel{R}q_0,   \qquad   p'\mathrel{R}q'   $$
    

Тут $\xRightarrow{\tau}$ означає нуль або більше внутрішніх переходів. Вимога, щоб проміжний стан $q_0$ залишався співвіднесеним із $p$, зберігає важливу можливість розгалуження, дозволяючи ігнорувати внутрішню роботу. Ван Ґлаббек і Вейланд започаткували й розвинули цю еквівалентність у [*Branching Time and Abstraction in Bisimulation Semantics*](https://ir.cwi.nl/pub/5564/5564D.pdf).

</details>

## Денотаційна рівність {#denotational-equality}

Денотаційна рівність залежить від вибраної семантичної області:

$$ \llbracket P \rrbracket = \llbracket Q \rrbracket $$

Сама область може бути побудована з трас, систем переходів з точністю до бісимілярності, множин результатів чи іншої математичної моделі. Денотаційне проєктування не задає одну універсальну рівність. Воно вимагає явно її вибрати й використовувати композиційно.

Зв’язок такий:

1.  Візьміть операційну систему.
2.  Виберіть потрібні спостереження.
3.  Виберіть семантичну область і рівність.

## Розгалуження як дані {#branching-as-data}

Розгалуження також може мати структурне представлення у вигляді дерев. Бінарний шлях можна подати послідовністю рішень «ліворуч/праворуч». Це корисно для префіксних дерев, ідентифікаторів виконання, діаграм рішень і адресації пам’яті.

У прикладі семантичної позиції в розгалуженні з розділу [Чому значення має бути першим](../denotational-design/semantic-view.md) це значення дерева навмисно відокремлено від одного бітового векторного кодування.

Конал Елліотт описував адресацію пам’яті через структуру ідеального бінарного дерева листків. Ідеться не про те, що кожна машина буквально зберігає дерево з вихідного тексту; композиційна модель дерева може виявити корисну структуру, приховану за пласкими числовими адресами.

## Порівняння {#comparison}

| Поняття | Предмет | Основне запитання |
| --- | --- | --- |
| Розгалуження потоку керування | Одне виконання програми | Яке продовження вибирається? |
| Детермінізм | Відношення переходів | Чи визначено наступний крок однозначно? |
| Конфлюентність | Відношення редукції | Чи можна звести розгалужені редукції докупи? |
| Еквівалентність трас | Послідовності спостережуваних дій | Чи допускають системи однакові траси? |
| Бісимілярність | Структура розгалужених переходів | Чи можуть системи зіставити переходи одна одної? |
| Денотаційна рівність | Вибрана семантична область | Чи мають програми те саме специфіковане значення? |

Ці поняття можуть доповнювати одне одного, але жодне з них не є синонімом іншого.
