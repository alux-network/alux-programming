## 定義 {#definition}

継続渡し形式（CPS）は、関数が値を直接返さず、結果を*継続*と呼ばれる別の関数へ渡す形でプログラムを書く方法です。継続はプログラムの残りを表します。

## 目的 {#motivation}

*   制御フローを明示し、プログラムから扱えるようにする。
*   ノンブロッキングIO、早期終了、コルーチン、バックトラッキング、並行スケジューリングなどの高度な変換を可能にする。
*   最適化や解析を単純化する目的で、コンパイラーの中間表現に使われる。

## 基本形式 {#basic-form}

直接形式：

```rust
fn add_one(x: i32) -> i32 {
    x + 1
}

fn main() {
    let y = add_one(41);
    println!("{}", y);
}
```

CPS形式：

```rust
fn add_one_cps(x: i32, k: impl Fn(i32)) {
    k(x + 1)
}

fn main() {
    add_one_cps(41, |y| {
        println!("{}", y);
    });
}
```

ここでは、`k`は継続です。`x + 1`を返すのではなく、`k(x + 1)`を呼び出します。

## 主な性質 {#key-properties}

*   関数呼び出しはすべて、継続への*末尾呼び出し*です。
*   現在の計算は呼び出し元に「戻り」ません。継続へ制御を移します。
*   プログラム内で制御フローが明示される。

## 高階関数との関係 {#relation-to-higher-order-functions}

*   CPSでは、継続は高階関数にすぎません。
*   計算の各段階では、次に何をするかを表す継続を受け取ります。

## デファンクショナライズとの関係 {#relation-to-defunctionalization}

*   CPSでは、継続は実際の関数値です。
*   デファンクショナライズは、継続関数を、次のステップを表すデータ構造（列挙型）と、それを解釈する`apply`関数に置き換えます。

## 自由モナドとの関係 {#relation-to-free-monads}

*   自由モナドの`FlatMap`構成子は、格納された継続そのものです。
*   自由モナドを解釈することは、継続がプログラムデータの一部であるCPSコードを実行するようなものです。
*   適切な自由モナド符号化は、CPSやデファンクショナライズされた継続表現と関連付けられます。

## 利点 {#advantages}

*   柔軟な制御フロー表現。
*   評価順を推論しやすくなる。
*   インタープリター、デバッガー、最適化器、非同期ランタイムの実装に有用。

## 欠点 {#disadvantages}

*   直接形式に比べて冗長。
*   人間には読みにくい場合がある。
*   末尾呼び出しをネイティブにサポートしない言語では、効率のために末尾呼び出し最適化が必要。
