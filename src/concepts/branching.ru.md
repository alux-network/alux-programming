Ветвление, детерминизм, конфлюэнтность, эквивалентность трасс и бисимуляция — разные свойства, связанные с альтернативами в вычислении.

```admonish note title="Семантическое место"
Ветвление потока управления — операционная структура. Конфлюэнтность — свойство отношения редукции. Эквивалентность трасс и бисимуляция сравнивают поведение. Денотационное равенство сравнивает смыслы в выбранной семантической области. Корректный проект явно указывает нужное равенство, не смешивая эти понятия.
```

## Поведенческая эквивалентность {#behavioral-equivalence}

У параллельных и интерактивных программ редко бывает лишь один конечный результат. Стандартной отправной точкой служит **система помеченных переходов**:

$$ \mathcal{L} = (S, A_{\tau}, \to) $$

где $S$ — множество состояний, $A_{\tau}$ — множество меток наблюдаемых действий вместе с внутренним действием $\tau$, а $\to\;\subseteq S \times A_{\tau} \times S$ — отношение переходов. Запись $p \xrightarrow{a} p'$ означает, что состояние $p$ может выполнить действие $a$ и перейти в состояние $p'$.

Поведенческая эквивалентность задаёт, какие различия между такими системами намеренно опускаются:

*   **Наблюдения линейного времени** следуют за завершёнными или частичными выполнениями и фиксируют происходившее
*   **Наблюдения ветвящегося времени** также сохраняют информацию о том, где были доступны альтернативы и когда был сделан выбор

Поэтому две системы могут допускать одни и те же трассы, но иметь разную структуру ветвления. Одна может выбирать между двумя действиями до взаимодействия, другая — откладывать выбор до его завершения. Последовательности действий совпадают, но будущие возможности различаются.

Спектр [линейное время — ветвящееся время](https://ir.cwi.nl/pub/5685/5685.pdf) ван Глаббека систематически описывает такие поведенческие эквивалентности. Это не шкала от слабой к сильной: в каждой точке сохраняется свой набор наблюдений.

## Ветвление в программах на Rust {#branching-in-rust-programs}

`if` выбирает ветвь в зависимости от условия:

```rust,noplayground
fn sign(x: i32) -> i32 {
    if x > 0 {
        1
    } else if x < 0 {
        -1
    } else {
        0
    }
}
```

`match` выбирает одну ветку по значению:

```rust,noplayground
fn day_type(day: &str) -> &str {
    match day {
        "Saturday" | "Sunday" => "Weekend",
        "Monday" | "Tuesday" | "Wednesday" | "Thursday" | "Friday" => "Weekday",
        _ => "Unknown",
    }
}
```

При фиксированных входных данных в детерминированном языке эти конструкции предсказуемо выбирают путь потока управления. Это свойство называется **детерминизмом**, а не конфлюэнтностью.

## Что такое конфлюэнтность {#what-confluence-means}

Отношение редукции конфлюэнтно, если два перехода из одного терма можно снова свести к общему результату:

$$ \begin{array}{ccccc} && a && \\ & \swarrow^{*} && \searrow^{*} & \\ b &&&& c \\ & \searrow^{*} && \swarrow^{*} & \\ && d && \end{array} $$

Формально, если:

$$ a \to^* b \quad\text{and}\quad a \to^* c $$

то должен существовать некоторый `d`, такой что:

$$ b \to^* d \quad\text{and}\quad c \to^* d $$

Конфлюэнтность допускает несколько путей редукции. Она означает, что эти пути совместимы и могут привести к общему последующему состоянию.

## Детерминизм и конфлюэнтность {#determinism-and-confluence}

У детерминированного отношения редукции из каждого состояния возможен не более чем один следующий шаг. Поэтому оно конфлюэнтно в простом смысле: конкурирующих вариантов одного шага, которые нужно согласовывать, нет.

Обратное неверно. Система может допускать разные порядки редукции и при этом быть конфлюэнтной, поскольку все порядки в итоге приводят к общему результату.

Обычные выражения Rust `if` и `match` демонстрируют детерминированный выбор, но сами по себе не иллюстрируют содержательную конфлюэнтность.

## Чёрч — Россер {#churchrosser}

Теорема Чёрча — Россера утверждает конфлюэнтность редукции лямбда-исчисления. Если терм разными путями редукции переходит к двум результатам, у этих результатов есть общий редукт.

Если нормальная форма существует, конфлюэнтность гарантирует её единственность. Это поддерживает рассуждения через равенства: порядок вычисления не меняет конечную нормальную форму.

Не переносите этот результат на произвольные императивные программы. Побочные эффекты, недетерминированное планирование, сбои и наблюдение промежуточных состояний могут различать порядки редукции.

## Трассы {#traces}

**Трасса** фиксирует последовательность наблюдаемых действий или состояний. Трассовая семантика намеренно сохраняет больше операционной информации, чем семантика, учитывающая только результат.

Две чистые функции могут возвращать один результат, пройдя через разные внутренние шаги. Они равны в денотации результатов, если эти шаги опускаются, но не обязательно равны в трассовой семантике.

При наличии эффектов перестановка условий может менять наблюдаемые результаты:

```rust,noplayground
fn is_admin() -> bool {
    println!("checked admin");
    true
}

fn is_user() -> bool {
    println!("checked user");
    true
}
```

Если сначала проверить `is_admin`, а затем `is_user`, или наоборот, классификация может оказаться эквивалентной, но трассы печати будут различаться.

Проектный вопрос состоит в том, входят ли эти сообщения в выбранную семантическую область.

## Эквивалентность трасс {#trace-equivalence}

Две системы эквивалентны по трассам, если в выбранной модели допускают одинаковые наблюдаемые трассы.

Эквивалентность трасс может опускать структуру ветвления. Две системы могут порождать одинаковые трассы, даже если одна фиксирует выбор раньше другой. Для интерактивных и параллельных систем это различие может быть важным.

## Бисимуляция {#bisimulation}

Бисимуляция связывает две системы переходов шаг за шагом. Когда одна система выполняет наблюдаемый переход, другая должна уметь ему соответствовать, а полученные состояния должны оставаться связанными.

Распространённые варианты:

*   **сильная бисимуляция**, сопоставляющая отдельные переходы
*   **слабая бисимуляция**, опускающая выбранные внутренние переходы
*   **ветвящаяся бисимуляция**, опускающая внутреннюю работу, но сохраняющая важную структуру выбора

Бисимуляция часто даёт более строгий способ сравнения поведения, чем эквивалентность трасс, поскольку учитывает, какие альтернативы остаются доступными в ходе взаимодействия.

<details>
<summary><strong>Истоки и формальные определения</strong></summary>

Милнер разработал наблюдательную эквивалентность процессов в книге [*A Calculus of Communicating Systems*](https://www.lfcs.inf.ed.ac.uk/reports/86/ECS-LFCS-86-7/ECS-LFCS-86-7.pdf). Затем Парк дал коиндуктивную характеристику соответствующей эквивалентности в работе [*Concurrency and Automata on Infinite Sequences*](https://wrap.warwick.ac.uk/id/eprint/47224/1/WRAP_Park_cs-rr-035.pdf), введя отношение наибольшей неподвижной точки и метод доказательства, ныне известный как бисимуляция. Милнер перенял и развил этот метод как основу рассуждений о поведении процессов.

**Сильная бисимуляция.** Для систем помеченных переходов отношение $R$ является сильной бисимуляцией, если из $p\mathrel{R}q$ следует для каждого действия $a$:

*   если $p\xrightarrow{a}p'$, то существует $q'$, удовлетворяющее $q\xrightarrow{a}q'$ и $p'\mathrel{R}q'$; и
*   если $q\xrightarrow{a}q'$, то существует $p'$, удовлетворяющее $p\xrightarrow{a}p'$ и $p'\mathrel{R}q'$.

Два состояния бисимилярны, если их связывает некоторая бисимуляция. Определение коиндуктивно: после сопоставления перехода состояния-преемники вновь должны удовлетворять тому же требованию поведения.

**Ветвящаяся бисимуляция.** В распространённой версии, не учитывающей дивергенцию, симметричное отношение $R$ является ветвящейся бисимуляцией, если $p\mathrel{R}q$ и $p\xrightarrow{a}p'$ влекут одно из двух:

*   $a = \tau$ и $p'\mathrel{R}q$; или
    
*   существуют состояния $q_0$ и $q'$, такие что
    
    $$   q \xRightarrow{\tau} q_0 \xrightarrow{a} q',   \qquad   p\mathrel{R}q_0,   \qquad   p'\mathrel{R}q'   $$
    

Здесь $\xRightarrow{\tau}$ означает ноль или более внутренних переходов. Требование, чтобы промежуточное состояние $q_0$ оставалось связанным с $p$, сохраняет важные возможности ветвления, позволяя игнорировать внутреннюю работу. Ван Глаббек и Вейланд ввели и развили эту эквивалентность в работе [*Branching Time and Abstraction in Bisimulation Semantics*](https://ir.cwi.nl/pub/5564/5564D.pdf).

</details>

## Денотационное равенство {#denotational-equality}

Денотационное равенство зависит от выбранной семантической области:

$$ \llbracket P \rrbracket = \llbracket Q \rrbracket $$

Сама область может быть построена на трассах, системах переходов по модулю бисимуляции, множествах результатов или другой математической модели. Денотационное проектирование не предписывает единого универсального равенства. Оно требует явно выбрать его и использовать композиционно.

Связь между понятиями такова:

1.  Начните с операционной системы.
2.  Выберите значимые наблюдения.
3.  Выберите семантическую область и отношение равенства.

## Ветвление как данные {#branching-as-data}

Ветвление также встречается как структура дерева. Бинарный путь можно представить последовательностью решений «влево/вправо». Это полезное представление для префиксных деревьев, идентификаторов выполнения, диаграмм решений и адресации памяти.

Пример семантической позиции ветвления в разделе [«Почему начинать нужно со смысла»](../denotational-design/semantic-view.md) намеренно отделяет смысл дерева от одного конкретного битового представления.

Конал Эллиотт описывал адресацию памяти через структуру совершенного бинарного дерева листьев. Смысл не в том, что каждая машина буквально хранит исходное дерево, а в том, что композиционная модель дерева может раскрыть полезную структуру, скрытую плоскими числовыми адресами.

## Сравнение {#comparison}

| Понятие | Предмет | Главный вопрос |
| --- | --- | --- |
| Ветвление потока управления | Одно выполнение программы | Какое продолжение выбрано? |
| Детерминизм | Отношение переходов | Однозначно ли определён следующий шаг? |
| Конфлюэнтность | Отношение редукции | Можно ли свести расходящиеся редукции? |
| Эквивалентность трасс | Последовательности наблюдаемых действий | Допускают ли системы одни и те же трассы? |
| Бисимуляция | Структура ветвления переходов | Могут ли системы сопоставлять переходы друг друга? |
| Денотационное равенство | Выбранная семантическая область | Имеют ли программы один и тот же заданный смысл? |

Эти понятия могут дополнять друг друга, но ни одно нельзя использовать как синоним другого.
