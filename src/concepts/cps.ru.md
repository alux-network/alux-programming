## Определение {#definition}

Стиль передачи продолжений (CPS) — способ писать программы, в котором функции не возвращают значения напрямую. Вместо этого они передают результат другой функции, называемой *продолжением* и представляющей остаток программы.

## Зачем он нужен {#motivation}

*   Делает поток управления явным и программируемым.
*   Позволяет выполнять сложные преобразования: неблокирующий ввод-вывод, досрочный выход, сопрограммы, возврат с перебором вариантов и планирование параллельных задач.
*   Используется в промежуточных представлениях компиляторов для упрощения оптимизации и анализа.

## Базовая форма {#basic-form}

Прямой стиль:

```rust
fn add_one(x: i32) -> i32 {
    x + 1
}

fn main() {
    let y = add_one(41);
    println!("{}", y);
}
```

Стиль CPS:

```rust
fn add_one_cps(x: i32, k: impl Fn(i32)) {
    k(x + 1)
}

fn main() {
    add_one_cps(41, |y| {
        println!("{}", y);
    });
}
```

Здесь `k` — продолжение. Вместо возврата значения `x + 1` мы вызываем `k(x + 1)`.

## Основные свойства {#key-properties}

*   Все вызовы функций являются *хвостовыми вызовами* продолжений.
*   Текущее вычисление никогда не «возвращается» к вызывающему коду, а переходит к продолжению.
*   Поток управления становится явным в программе.

## Связь с функциями высшего порядка {#relation-to-higher-order-functions}

*   В CPS продолжения — это обычные функции высшего порядка.
*   Каждый шаг вычисления получает продолжение, которое задаёт, что делать дальше.

## Связь с дефункционализацией {#relation-to-defunctionalization}

*   В CPS продолжение является настоящим значением-функцией.
*   Дефункционализация заменяет функцию-продолжение структурой данных (перечислением), представляющей возможные следующие шаги, и функцией `apply` для их интерпретации.

## Связь со свободными монадами {#relation-to-free-monads}

*   Конструктор `FlatMap` свободной монады и есть сохранённое продолжение.
*   Интерпретация свободной монады похожа на выполнение кода CPS, в котором продолжение является частью данных программы.
*   Подходящие кодирования свободных монад можно связать с CPS и представлениями дефункционализированных продолжений.

## Преимущества {#advantages}

*   Гибкое представление потока управления.
*   Упрощает рассуждения о порядке вычисления.
*   Полезен при реализации интерпретаторов, отладчиков, оптимизаторов и асинхронных сред выполнения.

## Недостатки {#disadvantages}

*   Более многословен по сравнению с прямым стилем.
*   Может быть труднее для чтения.
*   Для эффективной работы в языках без встроенной поддержки требует оптимизации хвостовых вызовов.
