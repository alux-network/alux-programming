## Визначення {#definition}

**Операційна семантика** описує поведінку програми за допомогою суджень про обчислення або переходів між **конфігураціями**. Конфігурація може містити фрагмент програми разом із середовищем, сховищем, продовженням чи іншим абстрактним станом машини.

Це математичний опис: він визначає, які обчислення чи переходи є допустимими. Інтерпретатор або віртуальна машина можуть реалізувати ці правила, але конкретна реалізація сама по собі не є визначенням.

```admonish note title="Семантичне місце"
Операційна семантика — це точна семантика, а не просто неформальні деталі реалізації. Вона пояснює поведінку правилами обчислення чи переходів. [Денотаційне проєктування](../denotational-design/design.md) ставить доповнювальне, попереднє проєктне запитання: які композиційні значення й рівності мають зберігати ці правила?
```

## Стилі операційної семантики {#styles-of-operational-semantics}

### Малокрокова (структурна операційна семантика) {#small-step-structural-operational-semantics}

Обчислення розбивається на атомарні переходи:

$$ \begin{aligned} 2 + 3 &\to 5 \\ (2 + 3) \cdot 4 &\to 5 \cdot 4 \to 20 \end{aligned} $$

Корисно для моделювання паралельності, чергування та часткового виконання.

### Великокрокова (природна семантика) {#big-step-natural-semantics}

Описує обчислення через кінцеві результати:

$$ (2 + 3) \cdot 4 \Downarrow 20 $$

Часто зрозуміліша для міркувань про програми, що завершуються.

## Формальні правила {#formal-rules}

Операційну семантику зазвичай задають **правилами виведення**. Розгляньмо просту арифметичну мову:

$$ E ::= n \mid E + E $$

Для обчислення зліва направо потрібні три правила:

$$ \frac{E_1 \to E_1'}{E_1 + E_2 \to E_1' + E_2} \qquad \frac{E_2 \to E_2'}{n + E_2 \to n + E_2'} \qquad n_1 + n_2 \to n_3 \quad \text{where } n_3 = n_1 + n_2 $$

Перші два правила визначають наступний редукований підвираз. Третє виконує додавання, коли обидва операнди вже є значеннями.

Траса обчислення:

$$ (1 + 2) + 3 \to 3 + 3 \to 6 $$

## Чому це важливо {#why-it-matters}

*   Надає **точну, схожу на машинну модель** виконання.
*   Основа для інтерпретаторів і віртуальних машин.
*   Допомагає міркувати про коректність, використання ресурсів і безпеку.

## Зв’язок з іншими поняттями {#relation-to-other-concepts}

*   **Вільна монада** надає синтаксис інструкцій і їх послідовного виконання. Операційні правила можуть описувати обчислення програми в такому представленні.
*   **CPS** робить продовження обчислення явним. Операційні правила можуть описувати, як значення передаються цим продовженням.
*   **Дефункціоналізація** замінює відоме сімейство функцій даними першого порядку й операцією `apply`. Операційні правила можуть описувати отримані явні стани машини.

Це об’єкти й перетворення, для яких можна задати операційну семантику. Самі вони не є операційною семантикою.

## На практиці {#in-practice}

Операційні правила можуть скеровувати роботу інтерпретатора й надавати точну модель для його перевірки:

*   **EVM** природно моделювати малокроковою системою переходів станів, а завершене виконання як ціле можна пов’язати з великокроковим судженням.
*   Малокрокові правила часто безпосередньо відповідають гілкам `match` в інтерпретаторі Rust.

$$ n_1 + n_2 \to n_3 $$

Повне відношення обчислення зліва направо можна представити кодом Rust:

```rust,noplayground
enum Expr {
    Num(i64),
    Add(Box<Expr>, Box<Expr>),
}

fn step(expr: Expr) -> Option<Expr> {
    match expr {
        Expr::Num(_) => None,
        Expr::Add(left, right) => match (*left, *right) {
            (Expr::Num(a), Expr::Num(b)) => Some(Expr::Num(a + b)),
            (left @ Expr::Num(_), right) => step(right).map(|next| {
                Expr::Add(Box::new(left), Box::new(next))
            }),
            (left, right) => step(left).map(|next| {
                Expr::Add(Box::new(next), Box::new(right))
            }),
        },
    }
}
```

Ця функція виконує один перехід. Повторне застосування дає показану трасу; повернення `None` означає, що вираз уже є значенням.

## Операційні та денотаційні запитання {#operational-and-denotational-questions}

Операційні правила дають змогу доводити безпеку, прогрес, межі ресурсів і відповідність реалізаціям. Обмеження виникає, коли операційні механізми вибирають раніше за задумане абстрактне значення: рішення реалізації можуть випадково стати семантичними зобов’язаннями.

Денотаційне проєктування не відкидає операційну семантику. Воно пропонує спершу визначити семантичну область, композицію та закони, а потім пов’язати з ними операційну модель.

| Погляд | Запитання |
| --- | --- |
| Денотаційний | Що означає програма як ціле? |
| Операційний | За допомогою яких переходів її обчислюють? |
| Коректність | Чи зберігають ці переходи задумане значення? |

Наступні відеофрагменти показують, чим небезпечно вважати операційні описи єдиним джерелом розуміння.
