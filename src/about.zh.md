# 关于 {#about}

本书提炼了一种软件思维方式，灵感来自 Conal Elliott 的**指称设计**。核心思想简单而深刻：

```admonish note title="指称设计"
*先定义程序的含义，再决定它如何运行。*
```

在这一视角下，计算不是不透明的步骤序列，而是透明的数学对象。我们从**规范**开始，以纯粹且可组合的方式描述程序*意味着什么*。这些描述采用代数结构表达，通常表现为 trait 或类型签名。**实现**——这些含义*如何*实现出来——则是独立且可互换的一层。

将含义与机制分离后，我们便能获得：

*   **清晰性**——程序读起来像精确的定义。
*   **可组合性**——各部分可以按代数规则组合。
*   **可重构性**——实现持续演进时，含义仍保持不变。
*   **正确性**——推理程序时可以采用等式推理，而非操作层面的推理。

这些指南旨在提供实用技术，帮助读者在现代编程语言中运用这一风格，尤其是 Rust，同时保留其数学根基的优雅与严谨。

本书有意区分三个层次：

*   **含义**说明所设计的值、关系与变换。
*   **表示**选择如何将这些含义编码为类型与数据。
*   **执行**选择如何让一种表示在机器上运行。

ALUX 与 Tolang 为许多示例提供了背景，但阅读本版并不需要了解它们。本书会先介绍相关词汇。
