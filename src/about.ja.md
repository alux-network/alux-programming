# 概要 {#about}

本書では、Conal Elliottの**Denotational Design**に着想を得た、ソフトウェアについての考え方をまとめています。中核となる考えは単純でありながら深遠です。

```admonish note title="Denotational Design"
*プログラムの実行方法を決める前に、その意味を定義する。*
```

この考え方では、計算は不透明な手順の列ではなく、透明な数学的対象です。まず、プログラムが*何を*意味するかを純粋かつ合成可能に記述する**仕様**から始めます。多くの場合、代数構造、トレイト、型シグネチャで表現します。意味を*どう*実現するかを担う**実装**は、独立して交換可能な層です。

意味と仕組みを分けることで、次の利点を得られます。

*   **明快さ** — プログラムが正確な定義のように読める。
*   **合成可能性** — 部品が代数的に組み合わさる。
*   **リファクタリングのしやすさ** — 実装が進化しても意味は固定される。
*   **正しさ** — 操作手順ではなく等式でプログラムを推論できる。

本書のガイドラインは、数学的な基盤の優雅さと厳密さを失わずに、現代のプログラミング言語、特にRustでこの設計を実践する技法を提供します。

本書では、意図的に三つの水準を区別します。

*   **意味**では、どの値、関係、変換を設計しているかを定める。
*   **表現**では、その意味を型やデータにどう符号化するかを選ぶ。
*   **実行**では、機械上で表現をどう動かすかを選ぶ。

例の多くはALUXとTolangに着想を得ていますが、この版を読むためにそれらを知る必要はありません。本書ではまず語彙を定めます。
