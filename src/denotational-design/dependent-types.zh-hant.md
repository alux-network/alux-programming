## 由值索引的型別 {#types-indexed-by-values}

當型別可以依賴某個值時，它就是*依賴*的。因此，依賴型別不僅能描述值的形態，還能描述該值必須滿足的關係。

例如：

*   `Vec<n, T>` —— 由長度索引的向量 `n`
*   `Matrix<rows, cols, T>` —— 由維度索引的矩陣
*   `Proof<p>` —— 某個命題的證據 `p`

例如：

```hs
append : Vec<n, T> -> Vec<m, T> -> Vec<n + m, T>
```

結果型別表明，將長度分別為`n`和`m`的向量拼接後，會得到長度為`n + m`的向量。

## 依賴函式 {#dependent-functions}

依賴函式型別寫作：

$$ \Pi (x : A).\,B(x) $$

對於每個值$x$（型別為$A$），結果的型別為$B(x)$。比較：

$$ \begin{aligned} f &\colon A \to B \\ g &\colon (x : A) \to B(x) \end{aligned} $$

$f$的結果型別是固定的。$g$的結果型別則可能隨輸入變化。

根據“命題即型別”的對應關係，型別可以陳述一個命題，而擁有該型別的項可以充當證明。這有助於構建 API，使無效狀態、轉換或組合無法被構造出來。

## 與指稱設計的關係 {#relationship-to-denotational-design}

指稱設計首先會問：

1.  語義域是什麼？
2.  哪些觀察與組合很重要？
3.  必須滿足哪些定律？

隨後，依賴型別可以將其中一些答案內化。型別索引可以記錄向量長度、協議狀態、棧深度、資源上限，或兩個構造指稱同一結果的證明。

順序很重要。複雜的型別無法補上缺失的含義。只有當索引命題已經描述了預期的語義區別或刻意選擇的表示不變數時，它才會強化規範。

```admonish warning title="不要混淆語義命題與表示不變數"
二者都可以編碼到型別中，但權威範圍不同。每個相容直譯器都必須保留語義命題；表示不變數則只約束選擇它的那種表示。
```

## 證明與可執行證據 {#proofs-and-executable-evidence}

證明會在給定假設下確立一個命題。性質測試、場景測試與單元測試則提供有限的可執行證據。將命題編碼為依賴型別，可能讓型別檢查器驗證證明項，但這並不會把測試變成證明，也不會讓編譯器成為命題的來源。

本書始終採用同樣的區分：含義與定律陳述義務，工具負責檢查或實現它們。

## 在 Rust 中運用該模型 {#applying-the-model-in-rust}

Rust 並非完全依賴型別語言，但 const 泛型、型別狀態、關聯型別與 trait 約束可以表達有用的索引關係。這些編碼方式能夠把檢查移到編譯期，而且通常保留高效的具體表示。

即便 Rust 無法表達完整命題，證明導向的思維方式仍然有價值。明確陳述不變數，編碼型別系統能夠強制的部分，併為其餘部分保留定律或測試。編碼服務於規範，而非取代規範。

```admonish example title="以位置為索引的網格"
[`typed-grid-rs`](https://github.com/tgrospic/typed-grid-rs)在穩定版 Rust 中實現了上述`Matrix<rows, cols, T>`構想。每個格子都是一個由座標索引的型別——`Pos0x0`、`Pos1x2`等等——而移動會返回一種位置*不同*的型別：

`Pos0x0.right()`指稱`Pos1x0`；越過邊緣不是執行時錯誤，而是無法透過型別檢查的程式，因為到達邊界時不會生成相應的移動操作。

這正是本節所述的提升：原本屬於值世界的座標被提升到型別中，有效導航於是成為總函式，並在編譯期接受檢查。這些標記型別的大小為零，因此索引命題不產生執行時開銷。
```
