依存型は、型システムで値に応じた命題と証拠を表現します。意味論的仕様の一部を符号化できますが、仕様自体を選ぶものではありません。型に組み込む前に、意図する性質を明確にする必要があります。

## 値で添字付けされた型 {#types-indexed-by-values}

値に応じて変化する型を*依存型*といいます。そのため依存型は、値の形だけでなく、その値が満たすべき関係も記述できます。

例：

*   `Vec<n, T>` — 長さで添字付けされたベクトル `n`
*   `Matrix<rows, cols, T>` — 次元で添字付けされた行列
*   `Proof<p>` — 命題の証拠 `p`

たとえば、次のようになります。

```hs
append : Vec<n, T> -> Vec<m, T> -> Vec<n + m, T>
```

結果の型は、長さ`n`と`m`のベクトルを連結すると、長さ`n + m`のベクトルができることを示しています。

## 依存関数 {#dependent-functions}

依存関数型は次のように書きます。

$$ \Pi (x : A).\,B(x) $$

型$A$の各値$x$に対して、結果の型は$B(x)$になります。次と比べてください。

$$ \begin{aligned} f &\colon A \to B \\ g &\colon (x : A) \to B(x) \end{aligned} $$

$f$の結果型は固定です。$g$の結果型は入力によって変わることがあります。

命題即型対応のもとでは、型で命題を述べ、その型を満たす項を証明として使えます。これにより、不正な状態、遷移、合成を構築できないAPIを実現できます。

## Denotational Designとの関係 {#relationship-to-denotational-design}

Denotational Designでは、まず次を問います。

1.  意味論的領域は何か。
2.  重要な観測と合成は何か。
3.  満たすべき法則はどれか。

依存型を使うと、これらの答えの一部を型の内部で表現できます。型の添字に、ベクトルの長さ、プロトコルの状態、スタックの深さ、リソース上限、二つの構成が同じ結果を表すことの証明などを記録できます。

順序が重要です。高度な型を使っても、不足している意味は補えません。添字付きの命題が意図された意味論上の区別、または意図的に選んだ表現不変条件をすでに記述している場合に限り、仕様を強化できます。

```admonish warning title="意味論的命題と表現不変条件を混同しない"
どちらも型に符号化できますが、権限の範囲は異なります。意味論的命題は、互換性のあるすべてのインタープリターで保持されなければなりません。表現不変条件が制約するのは、それを選んだ表現だけです。
```

## 証明と実行可能な証拠 {#proofs-and-executable-evidence}

証明は、明示された仮定のもとで命題が成り立つことを示します。プロパティテスト、シナリオテスト、単体テストは有限の実行可能な証拠を提供します。依存型に命題を符号化すれば、型検査で証明項を検証できる場合がありますが、テストが証明に変わるわけでも、コンパイラーが命題の出所になるわけでもありません。

本書全体で使うのと同じ区分です。意味と法則が責務を述べ、ツールがそれを検査または実現します。

## このモデルをRustに適用する {#applying-the-model-in-rust}

Rustは完全な依存型付き言語ではありませんが、constジェネリクス、typestate、関連型、トレイト境界によって有用な添字付き関係を表現できます。こうした符号化によって検査をコンパイル時に行え、多くの場合、効率的な具体表現を保てます。

Rustで命題全体を表せない場合も、証明指向の考え方は有用です。不変条件を明示し、型システムで強制できる部分を符号化し、残りは法則やテストで検証します。符号化は仕様に役立つものであり、仕様を置き換えるものではありません。

```admonish example title="位置を型で添字付けした格子"
[`typed-grid-rs`](https://github.com/tgrospic/typed-grid-rs)は、先ほどの`Matrix<rows, cols, T>`の考え方を安定版Rustで実現します。各セルは座標`Pos0x0`、`Pos1x2`などで添字付けされた型になり、移動すると*別の*位置型が返ります。

`Pos0x0.right()`は`Pos1x0`を表します。境界の外への移動は実行時エラーではありません。境界では該当する移動が生成されないため、型検査に通らないプログラムになります。

これは、この節で説明した持ち上げと同じです。値の世界に置かれる座標を型へ昇格させ、有効な移動を全域的でコンパイル時に検査される関数にします。マーカー型はサイズがゼロなので、添字付き命題による実行時のコストはありません。
```
