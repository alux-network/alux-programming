## 由值索引的类型 {#types-indexed-by-values}

当类型可以依赖某个值时，它就是*依赖*的。因此，依赖类型不仅能描述值的形态，还能描述该值必须满足的关系。

例如：

*   `Vec<n, T>` —— 由长度索引的向量 `n`
*   `Matrix<rows, cols, T>` —— 由维度索引的矩阵
*   `Proof<p>` —— 某个命题的证据 `p`

例如：

```hs
append : Vec<n, T> -> Vec<m, T> -> Vec<n + m, T>
```

结果类型表明，将长度分别为`n`和`m`的向量拼接后，会得到长度为`n + m`的向量。

## 依赖函数 {#dependent-functions}

依赖函数类型写作：

$$ \Pi (x : A).\,B(x) $$

对于每个值$x$（类型为$A$），结果的类型为$B(x)$。比较：

$$ \begin{aligned} f &\colon A \to B \\ g &\colon (x : A) \to B(x) \end{aligned} $$

$f$的结果类型是固定的。$g$的结果类型则可能随输入变化。

根据“命题即类型”的对应关系，类型可以陈述一个命题，而拥有该类型的项可以充当证明。这有助于构建 API，使无效状态、转换或组合无法被构造出来。

## 与指称设计的关系 {#relationship-to-denotational-design}

指称设计首先会问：

1.  语义域是什么？
2.  哪些观察与组合很重要？
3.  必须满足哪些定律？

随后，依赖类型可以将其中一些答案内化。类型索引可以记录向量长度、协议状态、栈深度、资源上限，或两个构造指称同一结果的证明。

顺序很重要。复杂的类型无法补上缺失的含义。只有当索引命题已经描述了预期的语义区别或刻意选择的表示不变量时，它才会强化规范。

```admonish warning title="不要混淆语义命题与表示不变量"
二者都可以编码到类型中，但权威范围不同。每个兼容解释器都必须保留语义命题；表示不变量则只约束选择它的那种表示。
```

## 证明与可执行证据 {#proofs-and-executable-evidence}

证明会在给定假设下确立一个命题。性质测试、场景测试与单元测试则提供有限的可执行证据。将命题编码为依赖类型，可能让类型检查器验证证明项，但这并不会把测试变成证明，也不会让编译器成为命题的来源。

本书始终采用同样的区分：含义与定律陈述义务，工具负责检查或实现它们。

## 在 Rust 中运用该模型 {#applying-the-model-in-rust}

Rust 并非完全依赖类型语言，但 const 泛型、类型状态、关联类型与 trait 约束可以表达有用的索引关系。这些编码方式能够把检查移到编译期，而且通常保留高效的具体表示。

即便 Rust 无法表达完整命题，证明导向的思维方式仍然有价值。明确陈述不变量，编码类型系统能够强制的部分，并为其余部分保留定律或测试。编码服务于规范，而非取代规范。

```admonish example title="以位置为索引的网格"
[`typed-grid-rs`](https://github.com/tgrospic/typed-grid-rs)在稳定版 Rust 中实现了上述`Matrix<rows, cols, T>`构想。每个格子都是一个由坐标索引的类型——`Pos0x0`、`Pos1x2`等等——而移动会返回一种位置*不同*的类型：

`Pos0x0.right()`指称`Pos1x0`；越过边缘不是运行时错误，而是无法通过类型检查的程序，因为到达边界时不会生成相应的移动操作。

这正是本节所述的提升：原本属于值世界的坐标被提升到类型中，有效导航于是成为总函数，并在编译期接受检查。这些标记类型的大小为零，因此索引命题不产生运行时开销。
```
