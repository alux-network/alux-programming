# ALUX Programming：后续内容与界面维护规范

本文面向维护此站的 Agent。新增章节、翻译、导航或控件时，应沿用现有结构与视觉层级；不要为单个新元素另建一套排版。工程说明、校对记录及内部检查结果留在工程文档中，不放进读者界面。

## 新增内容如何接入

1. 原始英文内容以 `src/` 的 Markdown 和 `src/SUMMARY.md` 为准。新增章节须同时登记目录，保留原有章节、链接、标题锚点、代码和公式。不要直接编辑生成的 `web/public/content.json` 或 `web/dist/`。
2. 使用 Markdown 的一个一级标题作为章名，二级标题表示章节内分节，三级标题表示子节。不要为获得某个字号而跳过语义层级，不用加粗段落冒充标题。
3. 通过 `web/scripts/content.mjs` 和现有本地化流程接入内容；更新翻译键、语言清单与必要的界面翻译。新增页面必须可在魔法世界和现实世界访问，保持章节、目录、前后章导航和分享元数据一致。
4. 新控件复用现有工具栏、图标与交互方式。新增文案须覆盖当前全部语言；不要把新英文字符串直接留在其他语种界面，也不要只靠 CSS 改变文本含义。

## 排版、字号与对齐

- 正文基础字号由 `reading-preferences.js` 统一决定：拉丁文和西里尔文 24px，中日韩 22px，阿拉伯文 26px。A−/A+ 必须同时调整正文和目录，两个世界共享设置。不要在单页写死字号覆盖用户偏好。
- 魔法世界翻页与滚动的文字尺度由 `reader-presentation.css` 统一管理。正文、标题、代码、行内代码、提示框、表格和插图须逐项同号同字体；不得只给 `.folio-content` 添加字号而漏掉 `.continuous-prose`。代码正文约为正文的 82%，最低 16px；代码语言、复制及运行入口最低 16px。代码不得折断原始语法，长行横向滚动。
- 字标保持两种世界同样的比例：ALUX 为 38px，“编程”及对应语言副标题为 20px，使用同一书名字体与首行对齐，侧栏标志画框为 62px。两者分清主副层级，不把副标题做成难以辨认的小字，也不把两个世界的颜色强行统一。
- 分卷标题应比章节条目醒目：当前为目录基础字号加 2px，章节名为基础字号减 2px。卷号与卷名对齐首行，子章节沿同一文字起始线排列；编号保留独立窄列。优先给卷名足够宽度，桌面中文侧栏让“Rust 中的语义驱动设计”自然保持一行。窄屏按可用宽度自然折行，不用均衡换行、截断或缩小标题来硬塞。
- 分节标题前保留清楚的段间留白，标题行高约 1.35。分页中把标题与后文保持在一起时，也必须保留与前一节的间距；页首标题不额外添加空白。
- 正文、列表、表格和提示框沿文章内容区对齐。新增区块使用现有内容宽度、段落间距及容器内边距，不以负边距、绝对定位或多个空格凑齐。
- 中文正文自然流动，不手动逐句换行，不把每句话锁成一行。标题可按完整语义断行；代码、API 名称和公式按各自语法保留。长链接、长标识符和表格不得撑出手机屏幕。
- 搜索结果以章节标题为主，分卷名为辅：章节标题在桌面约 27–32px、手机约 25–29px，分卷名约 17–18px；魔法世界沿用书籍衬线字体，现实世界保留中性界面字体与衬线章节标题。搜索未输入时只显示一句本地化标语“一个关键词，翻开下一页。”；输入后再显示匹配章节，摘要最多展示两行，避免说明文字淹没标题。不要恢复重复的搜索范围说明、“开始探索”及易混淆的“简介”推荐入口。新增结果条目必须与已有条目的文字起始边缘、分隔线和箭头位置一致。
- 侧栏页底标语至少 18px，并随目录字号适当增长。不得恢复低对比度的微小装饰字。书页页眉、页脚和页码沿用已有层级，不与正文争抢视觉重点。
- 图片和文字以图片实际可见画面的边缘对齐，不只对齐外层盒子。完整显示产生留白时调整容器布局，不拉伸或裁掉已经确认的主体。插图、透明人物和标志保留完整轮廓。

## 英文大小写与多语言

- 品牌名称固定为 `ALUX Programming`，`ALUX` 保持全大写。英文界面导航、按钮和模式名称沿用 `ui-english.js` 的约定，例如 `Magic World`、`Real World`、`Book View`。先复用现有文案键，不对所有字符串机械执行首字母大写。
- 原文标题、正文句子、书目名称保持作者原有大小写。代码、类型、函数、变量、路径、命令、URL、锚点和数学符号不参与界面大小写转换，不翻译或改写受保护的技术标识符。
- 翻译忠于原文的含义、逻辑、语气和技术边界，同时使用母语者自然的表达；不要按英文词序逐字硬译。术语与现有章节一致，同一概念不能在目录、正文和搜索结果中无故换名。
- 中文署名用“光之十一”，英文署名用“Shixi Lin”；双语材料可同时出现。中文欢迎语中 ALUX 的读音按已经确认的“阿拉克斯”。
- 当前支持英文、简体中文、繁体中文、日文、韩文、越南文、德文、西班牙文、俄文、乌克兰文和阿拉伯文。阿拉伯文布局按 RTL，代码和公式保持 LTR；图标、前后导航和对齐需按阅读方向检查。

## 工具栏与三端布局

- 音乐按钮放在顶部工具栏、紧接昼夜切换。字号和阅读外观控件形成一组，书签及阅读模式保留清晰的位置；不要把音乐开关变成另一个必须先打开的菜单。
- 手机端按已有网格重排，点击区域至少 44px，欢迎语按钮至少 48px 高。不得通过隐藏字号、书签或音乐功能来掩盖拥挤。桌面、平板和手机都要检查真实文字长度，特别是德语、西里尔文及 RTL。
- 提示贴近实际触发按钮，受视口边界约束，不压住正文的主要阅读区。阅读音乐提示默认 5 秒收起；悬停和调整音量时保留，离开后约 2 秒收起。键盘操作不能被倒计时打断，关闭按钮始终可用。音乐提示不显示重复的“阅读音乐”标题，直接呈现 20px 的开关说明和音量条；读屏名称仍保留。

## 材质、色彩与翻页

- 官方 ALUX 标志的几何结构必须保持一致。可按页面材质调整色调，不替换成近似图形。现实世界保持中性灰白或炭灰；魔法世界保留纸页与森林气质，不把整站改成同一种装饰风格。
- 日夜模式分别检查文字对比度。不要靠发光、高亮整页或过度加粗解决可读性问题；也不要把辅助文字淡到难以辨认。
- 白天的目录按钮使用浅暖橄榄底、深橄榄文字与细边框，避免作为强主按钮压过阅读内容；夜间保留深绿，不把白天按钮颜色直接套入夜间。
- 魔法世界白天的代码块使用浅暖灰底和深色语法配色，避免大块深绿压住纸页；夜间保持深色代码块。每组语法文字相对代码底色至少达到 4.5:1 对比度，不能直接把夜间的浅色高亮移到浅底。
- 章内和跨章翻页统一为 560ms 的纸页翻动，书框和中间书签保持固定。夜间纸页通过折痕、纸边和投影区分前后页，静止的阅读底色保持偏暗。新增样式不能覆盖 PageFlip 的位移、裁切或层叠关系。
- 尊重系统减弱动画设置。切换章节、语言、阅读模式和窗口宽度后须清理旧动画，不留下遮罩、重叠纸页或阻挡点击的透明层。
- 滚动阅读的背景铺满整段阅读容器及其内边距，白天使用低纹理浅羊皮纸，夜间使用稳定深墨绿。`page-book` 在滚动模式下保持透明，不再叠一张旧纸纹形成矩形底板。日间侧栏滚动条使用暖灰橄榄色，夜间保留深绿；不要用夜间的深色轨道分割浅色页面。
- 语言选择器的下拉箭头使用 `inset-inline-end` 等逻辑属性，RTL 时与文字、地球图标一起检查，不能与地球轮廓重叠。不要通过压扁或旋转地球图标掩盖布局问题。

## 插图与 GitHub 说明

- 章节插图的网页替换表统一放在 `scripts/content.mjs`，魔法、现实、滚动、翻页、静态回退及全部语言共用；不要只在某一个阅读器里替换。保留 `src/assets/` 原始图片及正文含义，新增网页素材放在 `public/art/`。详见 [ARTWORK.md](ARTWORK.md)。
- 插图以该章节的含义为依据，避免随机齿轮、辉光、无关符号和装饰堆砌。重画后检查透明 Alpha、完整轮廓、日夜底色、100% 边缘以及手机实际大小；压缩后也重新检查。工具不能锁定生成尺寸时如实记录实测尺寸，不把提示词里的 4K 当作实际结果。
- GitHub 默认介绍为根目录英文 `README.md`，十种本地化介绍位于 `docs/README.<语言代码>.md`。各版本顶部使用同一语言顺序、语言本名和相对链接，当前语言以加粗标识；不用国旗代表语言。阿拉伯语说明使用 RTL，命令保持 LTR。GitHub 的语言切换是静态链接，不伪称按地区自动跳转。
- 介绍先说明这本书讲什么，再提供目录、阅读和本地运行入口。保留作者、技术事实及原有许可说明，不增加宣传套话、AI 制作叙事或虚构的在线部署。网站初始语言与手动选择的行为仍由现有语言路由处理。

## 声音行为

- 入口只有欢迎语，没有背景音乐。欢迎语进入时尝试自动播放一遍，支持停止和重播；浏览器拦截时，在首次有效页面手势中重试。用户主动停止后，不因随后的普通点击再次自动播放。
- 魔法世界进入后默认播放阅读音乐，现实世界默认关闭。音符按钮单击直接开关；同一世界切换章节时不重复重置。离开阅读区停止音乐，切换后台暂停，恢复前台时遵守原来的开关状态。
- 新访客音量默认为 100%，表示音频文件本身的电平，不额外放大，也不改变设备系统音量。用户调整后记住选择。手机使用 Web Audio 的增益控制；不得只修改在 iPhone 上可能无效的媒体元素音量。
- 沿用已确认的配音角色和音频资产，不擅自替换音色、循环欢迎语或叠加入口背景音乐。欢迎文案改动时同步核对全部语种的实际音频。

## 修改后的必要检查与提交

1. 运行 `pnpm --dir web build`，确认翻译覆盖、技术标识符保护及静态路由生成通过。
2. 根据变更范围检查桌面、平板和手机；至少覆盖 320px、768px 和 1440px，以及中英文、长文案和 RTL。涉及所有语言的共用样式或新文案时检查全部语种。查看真实渲染和实际交互，不以源码或截图尺寸代替运行效果。
3. 检查目录标题层级、正文边缘、长标题换行、可点击区域、弹层边界、横向溢出及日夜对比。涉及翻页须实际检查章内和跨章、前进与后退；涉及声音须检查播放、停止、重播、音量和后台恢复。
4. 分享预览文件位于 `web/previews/`，中英文应同时可检查，并可直接进入对应语言的网站。更新分享构图后同步对应素材，不能用旧截图冒充新效果。
5. 只提交本轮授权的差异，保留其他工作。当前这一轮继续更新 [PR #2](https://github.com/alux-network/alux-programming/pull/2)，不另开 PR，不合并，不开启自动合并，不修改生产发布流程。后续独立任务遵从用户当轮指定的提交范围和 PR。

补充约定：侧栏搜索入口使用简短的“搜索 / Search”及各语言对应短标签，不恢复“搜索本书 / Search the Book”。提示框标题跟随正文字号，约为正文的九成且不低于 18px。魔法世界已移除底部“本章目录”；GitHub 项目入口放在侧栏底部、“小小积木。无限可能。”标语上方，替换那里的星形装饰。图标至少有 44px 点击区和本地化的读屏名称，链接到项目仓库。书页页脚、章末的星形装饰及页码保持原样，不在阅读工具栏或每张书页重复添加源码入口。手机工具栏需检查每两个按钮的可见区域是否重叠，不能只检查页面有没有横向滚动条。
