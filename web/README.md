# ALUX Programming — local preview

This independent web presentation preserves all 28 original chapters from `../src` and the existing mdBook publishing workflow. `/` opens the wizard chooser. Magic and Real world enter the same introduction directly, with a same-chapter world switch. The ALUX logo returns to the chooser. Full contents pages are available at `/contents.html` and `/real/contents.html`, with language prefixes where appropriate; chapter entries open the chosen reader directly. `/magic.html` remains a compatible entrance alias.

The chooser places a complete standing wizard in a misty forest clearing, with warm and cool light distinguishing the two entrances. Its larger language control uses a high-contrast surface. The forest artwork is generated at 1672×941 native pixels and ordinarily encoded to WebP; it is not an upscaled 4K asset. Reader palettes remain independent.

## Run locally

Use Node 22.18 or later and pnpm. The content build requires `mdbook` 0.4.52, `mdbook-admonish` 1.20.0 and `mdbook-katex` 0.9.4 on PATH. They can be installed with Rust's `cargo install <name> --version <version> --locked`; KaTeX must retain its default pre-render feature. `MDBOOK_BINARY` can select another path to the pinned mdBook executable.

Run `pnpm install`, then `pnpm dev` on `127.0.0.1:4173`. Development watches `src/` and `book.toml`. A translated Markdown edit rebuilds that edition; a canonical source/configuration edit rebuilds every edition. Reload follows a successful build. A compiler failure leaves existing reader JSON in place. `pnpm build` generates content, checks translations and strict TypeScript, builds Vite assets and writes direct static routes. `pnpm preview` serves that build on port 4174. `pnpm test` generates content and runs type checks plus focused unit and book integration tests. The original mdBook publishing configuration and workflow are unchanged.

## Content architecture

`scripts/mdbook.ts` derives a web-only configuration from the original `book.toml`. The custom renderer `scripts/mdbook-json.ts` serializes mdBook's processed Book, including part titles, separators, chapter order and nested children. Both readers receive one `ReaderBook` model defined in `src/book.ts`; neither parses `SUMMARY.md` or discovers chapters from filesystem order.

The JSON backend contains Markdown, not an HTML syntax tree. The same build therefore uses mdBook's official HTML renderer for Markdown, links and heading IDs after the existing admonish and KaTeX preprocessors. `scripts/reader-presentation.ts` adapts that rendered HTML for the reader's code toolbar, syntax colors, image mapping and bounded video clips. Two small web-only preprocessors normalize Windows line endings before KaTeX and protect its TeX annotations from Markdown escape processing; they do not modify source files.

English remains canonical in `src/chapter.md`. Optional translations live beside it as `chapter.zh.md`, `chapter.de.md`, etc. One `SUMMARY.md` supplies all editions. The web-only `scripts/mdbook-localization.ts` preprocessor substitutes a selected source before normal includes, admonitions and KaTeX; a missing translation uses English. Canonical chapter paths and explicit heading IDs stay unchanged. Optional leading metadata such as `<!-- reader: {"title":"导言","parts":{"Welcome":"欢迎"}} -->` supplies navigation labels; translated `index.<lang>.md` supplies part names. Do not add another language-specific SUMMARY or overwrite English during builds.

`scripts/book.ts` writes an already-localized `public/content/<lang>.json` from each edition's native mdBook JSON and HTML. Both worlds, search and static routes consume those models. The browser requests only selected editions and caches successful requests. `public/content.json` is an English compatibility output, not a translation manifest. Four legacy heading fragments remain explicit aliases in `scripts/heading-aliases.ts`. Reading-time estimates retain the canonical edition's values instead of comparing whitespace counts across writing systems.

SolidJS owns navigation, dialogs, bookmarks, language selection, theme and size controls in `src/reader-app.tsx`, `reader-ui.tsx`, `book-view.tsx`, `real-view.tsx` and `navigation-views.tsx`. Generated chapter HTML is opaque. `book-layout.ts` owns measurement, pagination and PageFlip lifecycle; `reader-audio.ts` owns media/Web Audio lifecycle, with declarative controls in `music-controls.tsx`. Small typed interface dictionaries live in `locales/ui/`; components use explicit message keys, and `ui-format.ts` handles variable labels. There is no prose dictionary, HTML-token alignment or DOM text translation pass. Node executes erasable build-script types; `tsc --noEmit` checks strict TypeScript and JSX.

The one-time `scripts/migrate-translations.ts --baseline <frozen-reader-directory> --output <source-directory>` tool converts approved reader snapshots back to source Markdown. Turndown is used only by this migration tool, never to compile or render a book. See [the migration and review record](docs/source-localization-migration.md) for preservation scope and the one legacy heading-metadata discrepancy.

After `pnpm build`, run `pnpm test:browser` for the production-build Chromium regression: all eleven languages at 320px, 768px and 1440px in both worlds and full contents, plus navigation/search/bookmark/language/mode/copy/music-control interactions. Install Playwright's Chromium with `pnpm exec playwright install chromium`, or point `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to an existing compatible Chromium executable. It serves the build temporarily on port 4175 and writes its report/screenshots under the project `output/reader-regression/` directory. These browser checks do not prove physical-device audio playback or live hosting/cache behavior.

## Reading

Agents adding chapters or interface content must follow [AGENTS.md](AGENTS.md) for alignment, typography, capitalization, localization, responsive behavior and verification.

The magic reader uses soft physical pages, visible chapter navigation, blank-paper clicks, touch swipes, keyboard turns and continuous reading. Text selection, links, code, tables and interactive regions do not trigger blank-paper turns. Arabic spreads begin on the right and advance in reading order. Long technical blocks remain complete in scroll regions; tables continue between whole rows. The toolbar keeps stable dimensions when navigation opens or closes. Book and scroll views share their text, code, caption and illustration sizes in `reader-presentation.css`. Scroll view has one continuous paper surface; its inner book container is transparent.

The Real world uses a quiet technical-document layout with neutral gray-white day mode and neutral charcoal night mode. It has one day/night toggle. Both readers share their day/night and font-size preferences. Base reading sizes are 24px for Latin and Cyrillic languages, 22px for Chinese, Japanese and Korean, and 26px for Arabic. Contents group headings use the base plus 2px; chapter entries use the base minus 2px. Both font-size controls scale the body and navigation together and remain available on phones. Interface labels use consistent English title case; original prose, heading anchors and technical identifiers retain their spelling. Both chapter boundaries and turns within a chapter use a 560ms physical paper animation; the cover and cloth bookmark remain stationary. Reduced-motion preferences bypass the animation.

My bookmarks is visible in each sidebar. Multiple saved chapters retain their world and reading position, can be opened or removed, and migrate the older single-bookmark setting. Bookmarks, reading preferences and manual language choices are stored on the current browser; no account or server-side reading collection is implied.

Magic book pages are numbered continuously across the whole book. The same pagination algorithm measures chapter offsets and renders the sheets; changing language, text size or viewport recalculates the total. Page numbers sit at the outer edges, with a compact range/total below the book. Continuous scrolling does not invent page numbers. Chapter-end contents links navigate to a dedicated full contents page. Its chapter links enter the selected chapter directly; they do not pass through part-opening pages. The toolbar Contents button still toggles the reading sidebar.

The current chapter appears immediately as readable sheets while fonts, images and whole-book numbering prepare. Provisional page numbers stay hidden. Fonts and images load concurrently, and decoded images are reused across chapter navigation. Reflow keeps the previous content until its replacement is ready; a noninteractive copy bridges PageFlip's first paint without duplicating anchors or starting embedded players.

When the current layout already has settled fonts, images and cached chapter counts, the reader reuses its freshly paginated preview sheets for PageFlip. Uncached layouts still wait for resources and measure every chapter before assigning continuous page numbers.

Embedded interview clips retain their original references and show their individual time ranges. The web generator supplies explicit YouTube playback start/end bounds; repeated thumbnails alone do not imply duplicate clips.

## Languages

The menu order is English, 简体中文, 繁體中文, 日本語, 한국어, Tiếng Việt, Deutsch, Español, Русский, Українська, العربية. English has no language prefix. The other paths use `/zh/`, `/zh-hant/`, `/ja/`, `/ko/`, `/vi/`, `/de/`, `/es/`, `/ru/`, `/uk/`, `/ar/`. The Real reader follows the language directory, e.g. `/zh/real/introduction.html`. HTML uses `zh-Hans` and `zh-Hant`. Old `?lang=` links and common Chinese locale aliases are canonicalized without losing the chapter or anchor.

All ten translations contain 1,860 prose units and 138 interface labels. Code, API identifiers, formulas, diagrams and reference titles retain their original technical spelling. Each language has received a semantic review. The build checks key coverage, protected tokens and empty translated links/emphasis. Arabic prose is RTL; code and math remain LTR. Original English Markdown remains authoritative and unchanged.

Resolution order is an explicit language path or legacy query, a saved manual choice, a session-cached IP-country result, then English. First visits use the public GeoJS country endpoint with a short timeout; only the resulting language is cached, not the returned IP address. A manual selection persists and takes precedence over later country detection. Unsupported countries and failed lookups fall back to English. Country detection does not infer a person's native language.

## Welcome voice and reading music

The gateway uses the owner-approved Qwen3 Uncle Fu character voice. The Chinese clip reuses the accepted performance; Japanese, Korean and Russian speech use phonetic brand spelling for clear pronunciation. Vietnamese, Ukrainian and Arabic use local OmniVoice cloning from that approved synthetic reference. The owner specified noncommercial use; OmniVoice model attribution: https://huggingface.co/k2-fsa/OmniVoice (CC-BY-NC), with code at https://github.com/k2-fsa/OmniVoice. No private or third-party person was cloned.

Eleven clips are mastered around -16 LUFS with true peaks below -2 dBTP; measured values and text are in public/audio/welcome/manifest.json. Welcome speech attempts playback on gateway entry and language change, plays once, has replay/stop controls, and stops when leaving. If autoplay is blocked, the first page click, touch or key retries playback; an explicit stop suppresses that retry. The gateway has no background music.

Reading music uses the owner-provided 在森林的呼吸里, with one audio instance across chapter changes and a Web Audio gain control for phone volume. Each entry into a reading world shows a small dismissible hint beside the music button: Magic starts music automatically when permitted, while Real defaults off. The note button follows the day/night control and directly toggles playback. Its title-free 20px hint dismisses after five seconds; hovering or adjusting holds it open, and leaving dismisses it after two seconds. A new visitor starts at 100% (unity gain, the audio file’s own level); manual volume changes are remembered. If autoplay is blocked, a page gesture retries music. Pausing lasts through chapter navigation. A hidden page pauses music. No audio is mixed over the welcome.
