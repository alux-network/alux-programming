    Семантичне місце

    Вільна монада — це представлення синтаксису інструкцій із вільно згенерованим послідовним виконанням. Функтор інструкцій уже визначає термінологію, а інтерпретатор відображає цей синтаксис у семантичну область. Це один потужний спосіб кодування, а не визначення денотаційного проєктування.

    Що таке вільна монада (версія для Rust)

    Вільна монада дає змогу:

    • Описати програму як дані — не запускаючи її відразу.
    • Пізніше інтерпретувати цю програму одним чи кількома способами.

    Уявіть собі:

    AST операцій з ефектами + bind/flat_map для їхнього поєднання в ланцюжок.

    Розділяються:

    • Синтаксис → перелік інструкцій.
    • Інтерпретація → відображення зі збереженням структури у вибрану семантичну область.

    «Вільна» означає, що структура монади породжується з функтора F без додавання рівностей, крім законів монади. Вибір F уже визначає синтаксис інструкцій; інтерпретація створеної програми надає їй конкретну денотацію.

    Реалізація в Rust

    Схематичне кодування

    У Rust немає прямих параметрів типу вищого порядку, тому для виробничого кодування вільної монади потрібні додаткові механізми на рівні типів або спеціалізований функтор інструкцій. Наведений код ілюструє задуману форму, але це не готова універсальна реалізація.

    Тип вільної монади

    #[derive(Clone)]
enum Free<F, A> {
    Pure(A),
    Suspend(F),
    FlatMap(Box<Free<F, A>>, Box<dyn Fn(A) -> Free<F, A>>),
}

impl<F: Clone + 'static, A: 'static> Free<F, A> {
    fn pure(a: A) -> Self {
        Free::Pure(a)
    }

    fn flat_map<B: 'static, G>(self, f: G) -> Free<F, B>
    where
        G: Fn(A) -> Free<F, B> + 'static,
        F: 'static,
    {
        match self {
            Free::Pure(a) => f(a),
            Free::Suspend(op) => {
                Free::FlatMap(Box::new(Free::Suspend(op)), Box::new(f))
            }
            Free::FlatMap(inner, g) => {
                Free::FlatMap(inner, Box::new(move |x| g(x).flat_map(f.clone())))
            }
        }
    }
}

    DSL: операції консолі

    #[derive(Clone)]
enum Console<A> {
    Print(String, A),
    ReadLine(fn(String) -> A),
}

// Smart constructors
fn print_line(s: &str) -> Free<Console<()>, ()> {
    Free::Suspend(Console::Print(s.to_string(), ()))
}

fn read_line() -> Free<Console<String>, String> {
    Free::Suspend(Console::ReadLine(|input| Free::Pure(input)))
}

    Інтерпретатор

    fn run_console<A>(mut prog: Free<Console<A>, A>) -> A {
    loop {
        match prog {
            Free::Pure(a) => return a,
            Free::Suspend(Console::Print(s, next)) => {
                println!("{}", s);
                prog = Free::Pure(next);
            }
            Free::Suspend(Console::ReadLine(f)) => {
                let mut buf = String::new();
                std::io::stdin().read_line(&mut buf).unwrap();
                prog = f(buf.trim().to_string());
            }
            Free::FlatMap(inner, cont) => match *inner {
                Free::Pure(a) => prog = cont(a),
                Free::Suspend(op) => prog = Free::Suspend(op), // minimal handling
                _ => unimplemented!(),
            },
        }
    }
}

    Використання

    fn main() {
    let program =
        print_line("What is your name?")
        .flat_map(|_| read_line())
        .flat_map(|name| print_line(&format!("Hello, {name}!")));

    run_console(program);
}

    Висновок

    • Синтаксис = enum Console (можливі інструкції)
    • Програма = Free<Console, A> (дані, що описують кроки)
    • Конкретна інтерпретація = run_console
    • Перевага: для тієї самої програми можна створити кілька інтерпретаторів — наприклад, виконати реальні операції вводу-виводу, записати журнал у файл або скомпілювати її іншою мовою.

    Зв’язок із продовженнями та CPS

    Стиль передавання продовжень (CPS) — це спосіб писати програми, у якому функції не повертають значення безпосередньо, а передають результат іншій функції — продовженню, що представляє «решту програми».

    Вільна монада — це, по суті, програма як послідовність кроків, де кожен крок каже:

    «Зроби це, а потім продовжуй решту».

    Ця «решта програми» і є продовженням — функцією, яка перетворює поточний результат на наступний крок.

    • У нашій вільній монаді для Rust:

      Free::FlatMap(Box<Free<F, A>>, Box<dyn Fn(A) -> Free<F, A>>)

      Box<dyn Fn(A) -> Free<F, A>> є продовженням.

    • Інтерпретуючи вільну монаду, ми виконуємо код у CPS:

      • Замість прямого повернення значень ми передаємо їх наступному продовженню.
      • У результаті маємо цикл із: current_instruction -> feed result into continuation -> next instruction

    • Зв’язок із CPS:

      • Вільні монади кодують CPS у структурі даних.
      • CPS є представленням потоку керування під час виконання тієї самої ідеї.

    Відповідність патернам GoF (Банди чотирьох)

    Вільні монади не належать до патернів GoF, адже походять із теорії функційного програмування. Однак вони узагальнюють або імітують кілька патернів:

    Патерн GoFЗв’язок із вільною монадами
    ІнтерпретаторКонструкція «AST + виконання» буквально відповідає патерну Interpreter — вільні монади просто надають AST і комбінатори.
    КомандаКожен варіант enum у DSL — це об’єкт-команда. Вільна монада поєднує їх, наче макрокоманду.
    КомпоновщикСтруктура AST (вкладені інструкції) утворює композицію команд.
    БудівельникЛанцюжок .flat_map — це плавний будівельник програм.
    ВідвідувачІнтерпретатор по суті обходить набір інструкцій як відвідувач.

    Чим вільна монада краща за ці патерни?

    • Патерни GoF — це ручна робота в ООП: потрібно визначати інтерфейси й класи та поєднувати їх.

    • Вільні монади є алгебраїчними: ви визначаєте дані для інструкцій і функції для їх інтерпретації.

    • Автоматично отримуємо:

      • послідовність виконання (flat_map)
      • композицію
      • кілька інтерпретаторів без зміни основної логіки

    Зв’язок із дефункціоналізацією

    Дефункціоналізація — це перетворення програми, яке замінює функції вищого порядку структурою даних першого порядку з представленням можливих функцій і інтерпретатором, що їх застосовує.

    У CPS продовження є функціями вищого порядку. Дефункціоналізація програми CPS замінює ці продовження переліком їхніх варіантів і функцією apply, яка їх виконує.

    За відповідного кодування вільну монаду можна пов’язати з дефункціоналізованими продовженнями у програмі, перетвореній на CPS:

    1. Почніть із версії програми в CPS. «Решту програми» містять функції-продовження.
    2. Дефункціоналізуйте функції-продовження, замінивши їх скінченною множиною варіантів типу даних.
    3. Отриманий тип даних першого порядку може мати таку саму форму інструкцій і продовжень, як і представлення вільної монади.

    Основні подібності

    • І вільні монади, і дефункціоналізація створюють представлення обчислення у вигляді даних та потребують інтерпретатора, який надасть цим даним значення.
    • Варіант FlatMap вільної монади містить продовження; дефункціоналізація замінює це замикання варіантом типу даних.
