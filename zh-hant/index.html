    ALUX 程式設計指南

    注

    本書將介紹理解並參與 ALUX 語義優先程式碼庫所需的基礎，從指稱設計的一項核心原則講起：先定義程式的含義，再決定程式如何執行。

    沿襲 Conal Elliott 的思路，本書將計算視為清晰的數學物件，而不是不透明的步驟序列。

    規範以簡單、可組合的能力 trait表達，用來描述程式意味著什麼。直譯器提供可互換的方式來實現這些含義。

    這樣一來，軟體的組合規則、實作義務和有效等式都更容易理解和測試。

    機制與含義

    概念與洞見用於說明實用的程式設計機制。指稱設計則說明如何判斷這些機制應當保留什麼。

    如何閱讀本書

    本書分三個層次閱讀：

    • 語義視角介紹指稱與組合性、定律與解釋，以及含義與表示之間的關係。
    • Rust 中的語義驅動設計將這一視角落實為小型能力、派生擴充、一階程式和輕量級直譯器。
    • 概念與洞見介紹重要的執行模型、編碼、變換與連結。

    語義原則不依賴特定語言。Rust 是主要實作語言；一條併發語言處理流水線將這些原則與 Tolang 連結起來。

    本書適合誰

    • 希望複雜軟體在不斷演進時仍能保持模組化、可組合、可測試且易於維護的程式設計師。
    • 希望連結範疇論、型別系統與程式設計的開發者。
    • 熟悉表示與操作技術的讀者——例如自由單子、延續傳遞風格（CPS）和去函式化——希望理解這些機制如何服務於語義優先設計，而非定義它。
    • 熟悉依賴型別與證明導向程式設計，並希望在編寫高效能 Rust 時運用這套思維方式的讀者。
    • 需要閱讀語義優先的 Rust 規範，並理解如何編譯並行語言而不以編譯器本身來定義語言的貢獻者。
